# Historical generator review — 5 September 2026

All 22 historical `_gen/*.py` scripts were fully read, totaling 4,258 lines. No script was executed, imported, edited, or moved by this review. The exact original paths, line counts, SHA-256 values, and eventual retirement paths are recorded in [the hash receipt](REAUDIT_LEGACY_GENERATORS_2026_09_05.json).

All 22 scripts warranted retirement. None is a necessary safe read-only helper: each contains top-level source/report writes, and the old audit script also launches local tools. They were absent from the current project mapping, CI, validator, QA, tests, and README commands. A search of those current entrypoints found no invocations, and all 22 modification times predated this supplemental review. There was no evidence of another worker editing them.

These are maintenance and evidence-integrity defects, not reportable cross-principal security vulnerabilities. Invocation requires a local operator already able to modify the repository; no game-client or network-callable path was found. The generated Lua embedded in these scripts is historical material, not the mapped runtime.

The Python code contains no deletion/recursive-deletion/move calls, network request calls, credentials or secret literals. Its practical destructive effect is truncating/replacing existing source and report files through `write_text`, `write_bytes`, or `copyfile`, without backups or a shared validation lock. Thirteen scripts hard-code `C:\Users\1thea\Projects\Florida-Man`, so running a copied script from another checkout can still modify the primary checkout; seven use working-directory-relative targets and two derive the root from their own location. The only subprocess caller is `audit_verify.py`; it uses argument arrays rather than a shell command string, but trusts local tool paths and has no timeout.

The parent completed the reversible quarantine: each confirmed file was renamed in the same ignored directory to `.py.retired`, preserving its exact bytes, and a directory README directs developers to current validation and QA tooling. This review independently checked every post-rename digest against its pre-rename receipt, confirmed all old `.py` entrypoints were absent, and fully read the new README. The original-to-current path mapping is in the receipt. This makes stale `.py` commands and ordinary `*.py` discovery fail. It is not a security sandbox: a deliberate Python invocation can still execute a `.retired` text file. Any future reusable migration should be designed separately with an explicit repository/output target, input hashes, dry-run diff, all-or-nothing writes, and validation; these historical scripts should not be promoted into current tooling.

Status at review completion: all 22 retired without content changes; no scripts executed or deleted. This review makes no claim that old generated output is current, correct, or safe to publish.
